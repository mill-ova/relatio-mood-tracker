# Relatio · Mood Tracker

Картка «How are you feeling?» на Home: п'ять живих іконок настрою — постійне «дихання», свій характер на тап і **своя вібрація на кожен настрій**.

Дизайн: Figma «Mood Tracker Card» `18594:76721`, компоненти — сторінка «↪ Mood Tracker» `18495:97231`.

```
prototype/index.html        ← ДЖЕРЕЛО ІСТИНИ по числах: цілісний SVG, усі таймінги, скраби й перемикачі
prototype/rn-layers.html    ← той самий рух, але складений із PNG-шарів, як у RN (для звірки вигляду)
react-native/               MoodTrackerCard.tsx + assets/ (3 шари × 5 настроїв × 2 теми × @1x/@2x/@3x)
docs/motion-and-haptics.md  спека руху, вібрації, розкрій арту, чеклист приймання
tools/                      скрипти, якими асети нарізані з Figma-експортів
```

**Залежності:** `react-native-reanimated` 3.x, `expo-haptics`, шрифт Poppins (Regular / Medium / SemiBold).

```tsx
import { MoodTrackerCard } from './react-native/MoodTrackerCard';

<MoodTrackerCard onSelect={mood => navigation.push('Journal', { mood })} />
```

## Логіка екрана

- П'ять настроїв у фіксованому порядку: Sad · Unpleasant · Neutral · Pleasant · Happy.
- У спокої всі п'ять «дихають» — кожна у своєму темпі й фазі.
- Тап: прес 0.94 → характер настрою (620–760 мс) + вібро-партитура → `onSelect(mood)`, далі екран журналу відкриває навігатор.
- **Вибраного стану немає.** Іконка повертається в idle; вибір фіксується вже на екрані журналу.

## Правила, які не варто «оптимізувати»

1. **Кожна квітка — це три PNG**, а не один: `glow_pulse` (світло, що дихає) під `flower` (тіло з запеченим глоу 80%) під `core` (ядро + обличчя). Так зроблено тому, що у Figma шари складають світло (`plus-lighter`), а в RN такого блендингу немає — при іншому розкрої квітка тускніє на 20–30/255. Деталі й виміряні цифри — у `docs/motion-and-haptics.md`.
2. **Обличчя (`core`) дихає слабше за тіло** (×0.55) і не похитується. Інакше риси пливуть — вони тонкі й блюрені.
3. **Рухаються тільки `transform` і `opacity`.** Ніяких анімацій `width`/`height`/`top`.
4. **Десинхрон обов'язковий.** У унісон ряд читається як блимання гірлянди, а не як п'ять живих істот.
5. **Асет більший за чіп** (104–114 dp проти 72) — це запас під глоу. Він центрується вручну, а не через flex, щоб три шари гарантовано збігалися. Не масштабувати нестандартно: блюри запечені під цей розмір.
6. **Вібрація — частина руху.** Біти стоять на тих самих мілісекундах, що ключові кадри анімації, і на iOS та Android це різні механіки (не «слабше», а інакше). При Reduce Motion рух прибираємо, а вібрацію лишаємо.
7. **Тап нічого не «вибирає».** Не додавати Selected-стан у картку.

## Що перевірено перед заливкою

- `npx tsc --strict` із реальними типами `react-native` / `react-native-reanimated` / `expo-haptics` — чисто.
- `npx esbuild` — синтаксис TSX чисто.
- Попіксельна звірка PNG-шарів із цілісним рендером SVG (`tools/verify_layers.py`): у Light відхилення 0.6–1.6/255, у Dark 3–5 у спокої та 12–17 на піку пульсу.
- Смуги на градієнтах халу: найдовша «полка» одного 8-бітного кроку 1.3–3.7 dp (видно від ~5–6) — 8-бітних PNG достатньо.
- Обидві теми і всі п'ять характерів тапу прогнані кадр за кадром у Chromium.

Чого **не** перевірено: реальний пристрій. Складання APK/IPA і живу вібрацію треба глянути очима й пальцями — чеклист приймання в кінці `docs/motion-and-haptics.md`.
